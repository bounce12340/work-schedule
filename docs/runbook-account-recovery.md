# 帳號救援手冊

> 有人進不去了。這份文件告訴你**照哪個順序試**、每一步**怎麼確認真的成功了**，
> 以及**哪幾件事要在今天就先確認好**——因為需要用到這份文件的那一天，通常也是
> 沒空現場研究的那一天。

這不是設計文件。設計上的取捨寫在 CLAUDE.md 的〈忘記密碼〉與〈破窗鎚〉，
這裡只講操作。

---

## 0. 先問一句：是哪一種進不去？

| 症狀 | 去哪一節 |
|---|---|
| 忘記密碼，信箱還收得到信 | [路徑 1](#路徑-1使用者自助重設最常見) |
| 忘記密碼，而且**是 `ADMIN_EMAILS` 名單內的帳號** | 一樣是[路徑 1](#路徑-1使用者自助重設最常見)。名單只擋管理者，不擋本人 |
| 忘記密碼，信箱本身也進不去 | [路徑 3](#路徑-3破窗鎚) |
| 按了「忘記密碼」，畫面說寄出去了，但信沒來 | [先查寄信記錄](#信沒來先去看寄信記錄) |
| 被停用（登入說帳號未核准／已停用） | 這不是救援，是[管理操作](#帳號狀態不對不是密碼問題) |
| 系統裡一個管理者都進得去的都沒有 | [路徑 3](#路徑-3破窗鎚)，而且要先看[第 4 節](#4-在需要它的那一天之前) |

## 路徑 1：使用者自助重設（最常見）

**做法**：請對方自己去 `/login` 按「忘記密碼」，輸入 email，收信，點連結，設新密碼。

**為什麼這是第一選擇**：它不需要任何後台權限、不需要有人在線上、也不會有人
拿到別人的臨時密碼。連 `ADMIN_EMAILS` 名單內的帳號都走得通——名單擋的是
「**另一位管理者**把這個帳號接管過去」（橫向），收得到寄到那個信箱的信則是
「**我就是本人**」（直向），兩者擋的東西不同。

**它會在哪裡斷掉**：

| 斷在哪 | 怎麼看出來 |
|---|---|
| 帳號不是 `approved`（待核准／已拒絕／已停用） | 系統仍然回 200 說「寄出去了」，但**什麼都不會寄**。這是刻意的（不能變成帳號列舉工具），代價就是這裡看不出差別 |
| 信被寄信商擋掉（退訂名單、退信、對方信箱滿） | `/admin` 的[寄信記錄](#信沒來先去看寄信記錄)會有一筆 `reset` 的失敗，帶寄信商的原因 |
| `AGENTMAIL_*` 沒設或設錯 | 同上，失敗原因會寫「未設定」或 `AgentMail 401/404` |
| 連結過期或已經用過 | 頁面會明說。重新索取一次即可（索取新的會作廢舊的） |

> **「畫面說寄出去了」永遠不代表寄出去了。** 那個 200 是防帳號列舉的固定回應，
> 不是寄信結果。要看真的結果只有一個地方：`/admin` 的寄信記錄。

### 信沒來？先去看寄信記錄

`/admin` → 「寄信記錄（最近 30 天）」。依種類分組：

- **密碼重設 / 驗證碼**＝交易信：使用者按了按鈕正在等。這兩種出現失敗**最嚴重**。
- **逾期提醒 / 櫻花樹的信**＝訂閱信：系統主動送的。

失敗那幾筆會顯示寄信商回的原文。常見的幾種：

| 訊息裡有 | 意思 | 怎麼辦 |
|---|---|---|
| `recipient is suppressed` / `message_rejected` | 這個收件地址在寄信商的退訂／退信名單上 | **寄信這條路對這個人已經斷了**，改走[路徑 2](#路徑-2管理者代為重設) 或[路徑 3](#路徑-3破窗鎚)。名單是帳號層級的，系統這邊改不了 |
| `未設定` | Worker 的 secret 沒設 | `npx wrangler secret put AGENTMAIL_API_KEY`（值不要貼進任何對話或 issue） |
| `AgentMail 401` | API key 無效 | 同上。分辨 key 與 inbox id 的方法見 CLAUDE.md |
| `AgentMail 404` | inbox id 不對（**不是** key 不對） | `AGENTMAIL_INBOX_ID` 要填 email 位址形式那一個 |
| 那一欄整個是空的 | 從來沒有寄過，或 `mail_log` 表還沒建 | 跑 `migrations/010-mail-log.sql` |

**那張表只證明到「寄信商收下了」為止**，證明不了對方讀到了。寄信商回 200
之後才自己丟掉的話，那一筆仍然是綠的。

## 路徑 2：管理者代為重設

**做法**：`/admin` → 找到那一列 → 「重設密碼」。臨時密碼**只顯示一次**，
抄下來，透過既有的聯絡管道（見下方）轉交，並提醒對方登入後立刻去改。

**它會在哪裡斷掉**：

- **`ADMIN_EMAILS` 名單內的帳號按不到這顆按鈕。** 那一列現在會顯示
  `設定檔指定` 徽章與一行說明，取代掉那四個操作（停用、降級、重設密碼、刪除）。
  這是刻意的：那四個本來就會被伺服器回 403，把按鈕留著只會讓人按下去、看到
  紅字、以為系統壞了。
- **系統裡一個登得進去的管理者都沒有**——那就只剩路徑 3。

> ### 不要拿 `ADMIN_EMAILS` 開路
>
> 「把那個 email 從 `ADMIN_EMAILS` 拿掉 → 重設 → 再加回去」是行得通的，
> 也**是這份文件唯一明確禁止的做法**。最後那一步一旦忘記，那個帳號就永遠
> 失去「不能被其他管理者接管」的保護，而**畫面上完全看不出來**。
> 路徑 3 做同一件事而且沒有這個地雷。

### 臨時密碼怎麼交

**不要用 email。** 需要走這條路的前提通常就是「信寄不到他那裡」。
用既有的、當面或即時的管道（LINE、當面、電話），並且：

- 交完就提醒對方**立刻登入並變更密碼**——臨時密碼的壽命應該以分鐘計。
- 對方所有裝置在重設的那一刻已經登出，所以「他還登著」不是可以拖的理由。

## 路徑 3：破窗鎚

`tools/reset-password.mjs`。它**不經過 Worker**，直接對 D1 下 SQL——所以
Worker 壞掉、AgentMail 掛掉、一個管理者都沒有的時候，它仍然能用。

### 什麼時候才用它

三種，缺一不可地都要成立才算「那兩條路走不通」：

1. 使用者的信箱進不去，或被寄信商永久擋掉（寄信記錄看得到）；
2. 或系統裡沒有任何一個登得進去的管理者；
3. 或那是 `ADMIN_EMAILS` 名單內的帳號、而本人的信箱同時也進不去。

### 做之前先確認

```bash
npx wrangler whoami          # 有沒有登入、是哪個帳號
```

沒登入就先 `npx wrangler login`。這一步在需要救援的當下才發現沒權限是最糟的
情況——所以[第 4 節](#4-在需要它的那一天之前)要求平常就先確認過。

### 執行

```bash
# 遠端（正式環境）
node tools/reset-password.mjs someone@example.com --yes

# 本機 D1（只影響 npm run dev 的資料庫，拿來練手很安全）
node tools/reset-password.mjs someone@example.com --yes --local
```

`--yes` 是刻意的：它會立刻改掉別人的密碼並把他所有裝置登出，不該因為打錯
一個指令就發生。**建議第一次先加 `--local` 跑一遍**，確認 wrangler 通、
輸出長什麼樣子，再對遠端下手。

### 每一步要確認什麼

| 看到什麼 | 代表 | 沒看到就不要往下走 |
|---|---|---|
| `✓ …的密碼已重設，所有裝置已登出` | 兩句 SQL 都跑完了 | 出現 `✗ wrangler 執行失敗` → 先處理登入／網路，密碼沒有被改 |
| **沒有**出現 `✗ 沒有任何一列被改到` | `changes` 不是 0，也就是那個 email 真的存在 | 出現了就是 **email 打錯**（大小寫、網域）。**這個檢查的存在理由就是它**：沒有它，打錯 email 會安靜地什麼都沒發生，而畫面看起來完全成功，然後對方拿著一組永遠登不進去的密碼來問你 |
| 臨時密碼那一行 | 只印這一次，畫面關掉就沒了 | 先抄下來再繼續 |

### 做完之後

1. **自己驗一次。** 用那個 email 與臨時密碼真的登入一次
   （用無痕視窗，不要弄亂自己現在的 session）。登得進去才算數——
   「SQL 跑了」與「這組密碼能用」是兩件事。
   > 驗完記得登出，不要把那個 session 留在你的瀏覽器裡。
2. **交付**，規則同[路徑 2 的臨時密碼怎麼交](#臨時密碼怎麼交)。
3. **提醒對方立刻變更密碼。**
4. **留一筆記錄。** 這支工具不經過 Worker，所以它**不會**寫進 `admin_activity`
   ——`/admin` 的操作記錄上完全看不到這件事發生過。這是它的本質（不經過
   Worker 才是它的價值），不是待修的缺陷，但也因此：**誰、什麼時候、為什麼
   對誰用了破窗鎚，要自己記在團隊看得到的地方**（issue、群組訊息都行）。

### 它不會動到什麼

只有兩句 SQL：換掉 `users.password_hash`、刪光那個人的 `sessions`。

`user_state`（他的排程）、`shares`、`reminder_feed`、`device_tokens`、
訂閱狀態**一個位元都沒碰**。重設密碼不會讓任何人掉資料——這一點要講得出來，
因為當事人多半正在擔心這件事。要確認的話：

```bash
npx wrangler d1 execute work-schedule-db --remote \
  --command "SELECT updated_at FROM user_state WHERE user_id IN (SELECT id FROM users WHERE email='someone@example.com');"
```

`updated_at` 應該還是重設之前那個時間。

## 帳號狀態不對，不是密碼問題

登入時說「帳號尚未核准」或「已停用」的，密碼是對的，重設沒有用。
`/admin` 改狀態即可。

**只有 `approved` 的帳號才能走自助重設**——停用中的帳號如果還能重設密碼，
停用就形同虛設。所以順序是：先核准／恢復，再請對方走路徑 1。

## 4. 在需要它的那一天之前

這一節是**現在**就要做的，不是出事那天才看的。

- [ ] **不只一個人進得去 Cloudflare。** 破窗鎚要 `wrangler login` 過的帳號，
      而 `wrangler login` 綁的是 Cloudflare 帳號。如果只有一個人有，那個人
      出國、離職、手機掉了，這條路就跟著斷——而它正是所有路都斷掉時的那一條。
      Cloudflare 的帳號設定 → Members 加第二個人。
- [ ] **那第二個人真的試過一次。** 「理論上有權限」與「當天做得出來」是兩件事。
      拿 `--local` 跑一次是最便宜的演練，什麼都不會壞。
- [ ] **兩位管理者的註冊信箱不是同一個信箱、也不在同一個網域下的同一個地方。**
      兩個都寄不到就等於一個都沒有。
- [ ] **`/admin` 的寄信記錄現在不是一片空白。** 空白有兩種意思——
      「都沒失敗」與「這張表根本沒建」，而這兩種在畫面上長得一模一樣。
      跑過 `migrations/010-mail-log.sql` 之後，寄一封測試提醒信確認有東西進去。
- [ ] **這份文件的位置有人知道。** 需要它的人不會是寫它的人。

## 為什麼不再多做一條自助的路

想過的：讓管理者產生一條「一次性重設連結」交給對方，取代臨時密碼。結論是**不做**。

- 對**名單外**的帳號，它跟現有的「重設密碼」比沒有多出任何能力——都是管理者
  產生一個憑證、當面交給對方。多一條路就多一條要維護、要測、會壞的路。
- 對**名單內**的帳號，它等於把那道保險拆掉：`ADMIN_EMAILS` 擋的就是
  「另一位管理者拿到這個帳號」，而這正是那件事，只是換了個名字。

真正的缺口不是「路不夠多」，是**每一條路都經過同一個寄信商**。補那個缺口
要的是第二個寄件管道（見 CLAUDE.md 的〈交易信與訂閱信要分家〉），不是第四條路。
