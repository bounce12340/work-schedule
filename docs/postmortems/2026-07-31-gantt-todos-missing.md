# 事故紀錄：專案頁的任務表與代辦項目整段消失

- **日期**：2026-07-31
- **影響**：專案頁在甘特圖底下的**任務表、代辦項目、專案筆記全部沒有渲染**；共享頁的專案卡片同樣受影響。資料完全沒有遺失
- **引入**：`f0f9951`「系統英文版：介面 i18n 與語言切換」
- **狀態**：已修復並上線（`4296ab6` / PR #8，Worker version `24bdec01`）

---

## 症狀

使用者回報：

> 我想確認為何專案進度下面的代辦項目為何不見了？

畫面上甘特圖與長條都正常，但底下應該有的東西一個都沒有。看起來像資料遺失或功能被拿掉。

實測的差異（同一份資料，壞的版本 vs 修好的版本）：

| 元素 | 壞的 | 修好的 |
|---|---|---|
| 甘特圖容器 | ✓ | ✓ |
| 甘特長條 | 1 | 1 |
| 任務列 | **0** | 1 |
| 代辦項目列 | **0** | 1 |
| 專案筆記編輯器 | **✗** | ✓ |
| 切換到其他頁 | 正常 | 正常 |

甘特圖在任務表之前建好，所以它活下來了——這正是使用者說「專案進度**下面**」的東西不見的原因。例外從任務表往上炸，把後面的專案筆記一起帶走。其他頁面各自有進入點，不受影響。

## 根因

代辦項目的列元素命名為 `tr`，而 `tr()` 是全域的翻譯函式：

```js
t.todos.forEach(td => {
  const tr = document.createElement('div');       // ← 遮蔽了翻譯函式
  const tcb = document.createElement('span');
  const inp = document.createElement('input');
  inp.placeholder = tr('代辦項目內容');            // ← TypeError: tr is not a function
```

`renderTodos()` 丟出例外 → 往上炸掉任務區塊的建構 → `renderGanttView()` 中斷 → 任務表與其後的專案筆記都沒有建出來。

受影響的兩處：

| 位置 | 被遮蔽的呼叫 |
|---|---|
| 專案頁 `renderTodos()` | `inp.placeholder`、刪除鈕的 `title` |
| 共享頁 `buildSharedGanttBody()` | 唯讀時 checkbox 的 `title` |

### 是全域搬進了區域變數的名字，不是反過來

這是本次最值得記住的一點。`const tr = document.createElement('div')` **早在 `d12bc1c`（子代辦項目功能）就存在了**，當時完全無害——那時候還沒有叫 `tr` 的全域函式。

真正的引入點是 `f0f9951`，它做了兩件事：把翻譯函式命名為 `tr()`，並把散落各處的中文字串包進 `tr(...)`。碰撞是在**全域那一側**造成的，區域變數那一行從頭到尾沒有被改過。

而 `tr()` 這個名字本身也是前一次同類事故的產物：更早的版本裡翻譯函式叫 `t()`，被 `gp.tasks.forEach(t => …)` 遮蔽（`t` 是這份程式碼裡 task 的慣用名），所以才改名為 `tr()`——結果 `tr` 又正好是 `<tr>` 表格列與 todo row 的自然縮寫。**兩次都是同一個機制，第二次是修第一次時搬進去的。**

## 為什麼 code review 沒攔下來

不是因為 diff 看不到。那一行就在同一個 hunk 裡，距離被改壞的那一行只有兩行：

```diff
@@ -3527,7 +3766,7 @@
         t.todos.forEach(td=>{
           const tr=document.createElement('div'); tr.className='todo-row';
           const tcb=document.createElement('span'); ...
-          const inp=...; inp.placeholder='代辦項目內容';
+          const inp=...; inp.placeholder=tr('代辦項目內容');
```

碰撞就攤在眼前，但它是一行**未變更的 context**。審查時眼睛跟著 `+`／`-` 走，context 只當背景讀——而這個 bug 的全部資訊都在 context 那一側。

> 大範圍的機械式改名（把 N 處字串包進某個函式）不能只審 `+` 行。要問的是：**這個名字在每一個被改到的 scope 裡都還指向我以為的東西嗎？**

## 為什麼自動化檢查沒攔下來

三道檢查一條都抓不到，而且都不是疏漏：

| 檢查 | 為什麼沒用 |
|---|---|
| `node --check` | 變數遮蔽是**合法的 JS**，語法檢查本來就會過 |
| `npm test`（當時 101 項） | 涵蓋 occurrence 引擎、三方合併、樂觀鎖、富文字過濾器，全都不碰前端整合 |
| Worker／D1／cron | 與這條 render 路徑完全無關 |

`CLAUDE.md` 的驗證第 0 條（新增前端函式必須在瀏覽器走過那條路徑）也擋不住——這次**沒有新增任何函式**，只是把既有字串包進 `tr()`。

**上一次事故（`2026-07-30-register-error-1101`）的教訓是「本機全綠不等於線上會動」；這一次是「全綠也可能只是沒有人跑過那條路徑」。** 兩者的共同點是：綠燈的涵蓋範圍與實際風險沒有交集。

### 全檔掃描的結果

修完之後對整份 `index.html` 做了一次完整掃描（追蹤大括號深度以分辨頂層與內層綁定，並跳過字串／樣板／註解／regex 字面值）。IIFE 頂層共 239 個識別名，掃出兩處遮蔽：

| 位置 | 判定 |
|---|---|
| 甘特圖月份刻度的 `const tick = document.createElement('div')` | **同一個 bug class，尚未引爆。** 頂層的 `tick()` 是每秒更新的時鐘函式。那個 while 迴圈裡目前沒有人呼叫 `tick()`，所以還沒出事——但只要有人在那段加一行就會炸。已改名為 `tickEl` |
| `threeWayMerge()` 內的 `const items = tmMergeList(...)` | **刻意保留。** 它遮蔽的是資料變數而非函式，而且 `threeWayMerge` 是純函式，本來就不該碰到全域的 `items`；名字與同段的 `gantt`／`majors`／`logs` 對稱。改名只會破壞可讀性 |

`tick` 那一處自 `c1d4622`（專案骨架）就存在，潛伏了整個專案的生命週期。

### 新增的靜態檢查

`tests/shadow.test.mjs` 只管**函式**被遮蔽，不管資料變數——後者的失敗模式是安靜的錯值而不是 TypeError，而且有正當的例外（上表的 `items`）。把兩者混在一起會讓這個測試充滿必須逐一豁免的條目，很快就沒有人理它。

三項測試：

1. 頂層函式清單本身有抓到東西（`> 50` 個，且 `tr`／`tf`／`weekName`／`commit`／`renderAll` 都在）——**沒有這一項，解析一壞掉另外兩項就會空轉並永遠是綠的**
2. 沒有區域變數遮蔽頂層函式
3. 沒有函式參數遮蔽頂層函式

## 教訓

1. **大範圍機械式改名要審 context，不只審 `+` 行。** 這次的碰撞就在被改的那一行上面兩行，是一行沒有變更的 context。改名的風險不在被改到的地方，而在**改完之後那個名字在各個 scope 裡指向什麼**。
2. **修 bug 時搬進來的新名字要先確認沒被用過。** `t()` → `tr()` 是為了修第一次的遮蔽，結果直接踩進第二次。改名修碰撞之前，先掃一次新名字。
3. **「某個區塊不見了」通常是渲染炸掉，不是資料不見。** 兩次都是這個症狀，兩次都很像資料遺失。診斷順序應該是先開 console 看例外，而不是先去翻 localStorage——這次先確認了程式碼還在（30 處 `todos` 參照）、再在瀏覽器裡跑一次，才看到 `tr is not a function`。
4. **靜態檢查抓不到的東西，要嘛寫成靜態檢查，要嘛就會再發生一次。** 前一次事故在 `CLAUDE.md` 留了規則，但規則不會執行。同一個 bug class 隔了兩次才被寫成測試，中間那次的代價是使用者回報。
5. **潛伏的同類問題要一起掃。** 只修被回報的那兩處，`tick` 會繼續躺在那裡等下一個人。修完一個 bug class 之後對全檔掃一次同型態，成本很低。
