日期：2026-10-02
狀態：**設計定案**（六個問題已由使用者裁決，見〈使用者的決定〉）

兩個功能同一批做，彼此沒有關係——放在一起只是因為使用者同一次提出。實作時
**各自獨立**，一個壞掉不影響另一個。

# 第一部分：專案的夥伴

## 一、為什麼「階段」不存起來

`gp.pet` **只存一個字串**（物種 id，例如 `'deer'`），`null` 代表沒選。
**第幾階一律算出來，不存。**

這與 occurrence 引擎、遊戲化是同一條原則，而三個理由在這裡逐條成立：

| 理由 | 在這個功能裡的具體形狀 |
|---|---|
| 存帳本就要合併帳本 | 兩台裝置各自勾掉幾個任務，`threeWayMerge` 就要長出「階段怎麼合」的第二套語意。算出來的話，合併只合任務，階段自己跟著對 |
| 帳本會跟資料脫節 | 刪掉一個已完成的任務，完成度會降——**動物就該退回去**。存起來的階段不會退，然後畫面與資料說的是兩件事 |
| 存檔格式不必升版 | `gp.pet` 是純新增欄位，`normalizeGanttProjects` 補 `null` 就好。**不必動 `STORAGE_VERSION`**（下方〈為什麼不升版〉有完整理由） |

**免費得到的一件事**：被分享者勾完你的任務，你的動物會跟著長大——因為階段是算出來的，這條**不必寫任何程式碼**。

## 二、五階，以及「100% 才是成年」

```
petCompletion(gp) = 已完成任務數 ÷ 總任務數        （沒有任務＝0，不是 NaN）
```

| 完成度 | 階段 key | 給人看的名字（幼體 → 成年之間） |
|---|---|---|
| 0%（含還沒有任務） | `baby` | 幼體 |
| 1–24% | `small` | 剛長大一點 |
| 25–49% | `half` | 半大 |
| 50–74% | `big` | 接近成年 |
| 75–99% | `almost` | 就快了 |
| **100%** | **`adult`** | **成年** |

**「100% 才是成年」是這個功能的全部重點。** 99% 不是成年——那一刻的差距正是
它要表達的東西。實作上不是比 `>= 100`（浮點數會咬人），而是**直接問
「每一個任務都 `done` 了嗎」**，與分數分開判斷。

**任務數少時會跳階，刻意不補。** 3 個任務的專案只走得到 3 階（0% → 33% →
67% → 100%，`small` 與 `almost` 永遠不出現）。那是誠實的：它反映的是「這個
專案只有三個里程碑」。為了讓動畫漂亮而插值，等於讓畫面說一件資料沒有說的事。

## 三、八種夥伴

使用者點名了小鹿→公鹿、小鳥→老鷹、小兔→成兔、以及冷杉／松樹，其餘由我提案。

| 幼體 → 成年 | 長大時看得出來的差別 |
|---|---|
| 小鹿 → 公鹿 | 長出鹿角 |
| 小鳥 → 老鷹 | 展翅、喙變尖 |
| 小兔 → 成兔 | 耳朵拉長、身體變壯 |
| 小貓 → 大貓 | 趴著 → 坐挺、尾巴變長 |
| 小狐狸 → 狐狸 | 尾巴變蓬 |
| 小龜 → 大龜 | 龜殼紋路長完整 |
| 小苗 → 高冷杉 | 尖塔形往上抽高 |
| 小苗 → 松樹 | 傘形往兩側展開 |

**全部是 inline SVG、顏色走 CSS 變數、零外部圖檔**——「單檔、零依賴」是專案
前提，`<img src>` 會讓離線開啟破圖（同〈氛圍層的三個實作決定〉）。

寫法照 `sakuraArt()`：**一個物種一個函式，階段決定畫幾個零件**，不是 8 × 6 = 48
張圖。幼體與成年必須看得出來是**同一隻長大了**，不是換了另一種動物——同
〈第 5 階回到第 0 階的樣子〉那條：多畫一個零件來湊差別是錯的。

兩種植物刻意**共用同一棵小苗**：它們的差別在成年的形狀（尖塔 vs 傘形），
而幼苗本來就長得一樣。這不是偷懶，是對的——使用者選的是「它會長成什麼」。

## 四、開機畫面：不新增第二個遮罩

櫻花留在中間（現有的 CSS、測試與 `check-ambience` 的九條斷言**一行都不動**），
夥伴縮小排在它**下面一列**。

**整排放進同一個 `.boot-sakura` 容器**，這是這一段最重要的實作決定：
`pointer-events:none`、CSS 的 1200ms 上限（JS 不跑也會走）、
`prefers-reduced-motion` 的 `display:none` **全部免費繼承**。

另開一個容器的話，那三個不變量就要再寫一次，而漏掉任何一個的症狀都已經
在〈開機的櫻花：它是遮罩，不是關卡〉記過：**一張永遠蓋住整個 app 的紙**。

| 決定 | 理由 |
|---|---|
| **最多 4 隻**，更多顯示「+N」 | 手機寬度放不下第五隻。Pro 不限專案數，不設上限的話畫面會變成動物園 |
| **按完成度由高到低排** | 最接近完成的先看到。開機那一秒鐘要說的是「哪一個快好了」 |
| **沒選夥伴的專案不佔位置** | 空位要靠「軌道也要留等高空位」那種補償，而這裡沒有對齊的需求 |
| 階段順序從 `PET_STAGES` 取，**不另外抄一份** | 同〈階段順序從 `GAME_STAGES` 取〉：抄出來的那一份遲早走鐘 |

## 五、選夥伴的入口

甘特專案的標頭一顆小按鈕，開一個八選一的面板（＋「不要夥伴」）。
照「不在」那個面板的形狀：**固定清單、不自由輸入**——自由輸入要處理貼進一
整段文字、輸入法中途的組字，以及「這是不是一個 emoji」這個沒有好答案的問題。

- **帳號頁不放第二份。** 專案頁已經看得到每一隻，帳號頁再放一份就是
  〈不要兩邊各放一份〉——同一份狀態兩個顯示位置，遲早不同步。
- 新增的前端函式**一律加 `pet` 前綴**。遮蔽事故發生過兩次（見〈多語系〉），
  而這一段會一次加好幾個頂層函式。

## 六、為什麼不升 `STORAGE_VERSION`

`absences` 那次升版了，這次不升——差別要寫清楚，否則下一個人會以為
「加欄位就要升版」：

| | `awayDates` → `absences` | `gp.pet` |
|---|---|---|
| 性質 | **形狀改變**（日期陣列 → 物件陣列） | **純新增**，舊存檔沒有它 |
| 舊存檔讀起來 | 直接讀 `.absences` 會是 `undefined`，於是「本來就有的那幾天」看起來像「對方刪掉了」——資料會靜靜消失 | `normalizeGanttProjects` 補 `pet: null`，畫面就是「還沒選夥伴」 |
| 要不要 migration | **要** | **不要** |

判準是：**舊存檔在新程式碼底下讀起來會不會錯**。會錯才升版；只是少一個
可選欄位，正規化補上就對了。

## 七、資料鏈的收尾（漏一個就是靜默的資料遺失）

照 CLAUDE.md〈資料模型的收尾〉那份清單逐一走過：

| 地方 | 要做什麼 |
|---|---|
| `snapshot()` | 把 `pet` 寫出去 |
| `applySnapshot()` | 經 `normalizeGanttProjects` 讀回來 |
| `normalizeGanttProjects()` | **不在白名單內的字串一律回 `null`**，不是原樣留著 |
| `threeWayMerge()` | 不必特別處理：它以 stableStringify 比對整個專案，`pet` 自動納入 |
| `clearLocalData()` | `ganttProjects = []` 已經涵蓋 |
| `seed()` | 示範專案給一隻（讓 `tools/` 的腳本有東西可量） |
| `mergeSharedEdit()` | **一行都不用改**，但要有測試守著 |

最後一列是重點。`mergeSharedEdit` 的甘特分支回 `{ ...current, tasks }`——
`pet` 來自 `current`（擁有者的資料），所以**被分享者改不到它**。
那不是靠權限判斷擋住，是**路徑本身走不到**；但照〈`listSessions` 的
`WHERE user_id = ?`〉同一條規則，仍然要有測試，否則哪天有人「順手」把
`pet` 加進那個展開式就沒有東西會紅。

`normalizeGanttProjects` 的白名單是**正確性不是美觀**：`pet` 的值會被拿去查
畫圖的函式表，一個不認得的字串在畫面上的症狀是「那一格空白」——而空白與
「還沒選」長得一模一樣。

# 第二部分：手機版日曆的滑動 bar

## 八、誤觸的根因，以及它為什麼不是 bar 能解決的

使用者回報「手機版日期的框選很容易誤觸」。根因在這一行：

```js
grid.addEventListener('touchstart', e=>{
  const d = dateOfEvent(e.target);
  if(d) startAt(d);        // ← 手指一放下就選了
}, { passive:true });
```

**手指一放下，那一天就已經被選起來了。** 想捲動的人只是把手指放在日曆上，
而那個動作與「我要選這一天」在程式裡是同一件事。手指再稍微飄過格子邊界，
`touchmove` 就把它變成選一整段區間。

加 bar 擋得住「碰到日期」——但只擋得住**走 bar 那條路的人**。
直接用手指捲日曆的人照樣誤觸，而那是最自然的動作。所以兩個都要做：
**bar 給一條不會碰到日期的路，修根因讓碰到也不會出事。**

## 九、從第一個明顯的移動方向判斷意圖

| 你做什麼 | 結果 |
|---|---|
| 點一下不動 | **放開手**才選那一天 |
| 先**橫向**滑（`|dx| > |dy|`，超過門檻） | 選區間——之後要往下拉幾週都可以 |
| 先**直向**滑（`|dy| > |dx|`，超過門檻） | 捲動，**這一次的觸控一天都不選** |

三個實作要點：

- **意圖只在第一次超過門檻時決定一次**，之後不再改。否則橫向開始、往下拉
  到第三週時方向變成直向，選取會在中途被取消——而使用者正在拉。
- **判定為捲動之後整個鎖死**（到 `touchend` 為止），不只是「這一下不選」。
  不鎖的話手指在捲動中途稍微橫一下就突然開始選取。
- **桌機的滑鼠路徑一個字都不動。** `mousedown` 本來就沒有這個問題——滑鼠不
  用按著不動來捲頁面。

### ⚠️ 這是取捨，不是純好處

**「從某一天直接往下拉」選區間會變成捲動**，要先稍微橫一下才開始。

使用者同意了，而理由是：直向拉正是最常誤觸的那一個動作，而 bar 本身就是為
直向捲動而存在。但這條**一定要寫下來**——日後有人覺得「往下拉應該要能選」
而把它改回去時，要知道那會把誤觸一起帶回來。

## 十、bar 的規格

| 決定 | 理由 |
|---|---|
| **貼右邊**，不是左邊 | 左邊是 iOS 的返回手勢（從左緣往右滑），放那裡會打架 |
| 顏色走 **`--panel`**，不寫死白色 | 亮色下它就是白的；暗色下自動變深。寫死白色在暗色主題下是一道燈，而 `check-contrast.mjs` 兩種主題都量 |
| 平時半透明、按下變不透明 | 使用者指定。平時不搶走日曆的注意力 |
| **只在日曆頁出現** | 使用者指定。別的頁沒有「誤觸日期」這個問題，多一個固定元素只是多一個會擋到東西的東西 |
| 補 `env(safe-area-inset-*)` | 它是固定元素。不補的話真機上下緣被動態島與 home indicator 蓋住——AI 面板實際踩過這個坑 |
| **窄，而且只有 bar 本身吃點擊** | 不做成看不見的全屏遮罩。`.ai-panel[hidden]` 那個 bug 的形狀就是「關著卻佔著」 |
| 拖它 → `window.scrollTo`，**不是** `scrollBy` | 位移要對應「整頁的哪個位置」，累加會因為每次 touchmove 的間距不均而漂移 |

## 十一、驗證

| 驗什麼 | 用什麼 | 為什麼不能只靠別的 |
|---|---|---|
| 完成度、五階門檻、**100% 才成年**、正規化白名單、舊存檔不升版也讀得到 | `tests/pet.test.mjs`（從 `index.html` 抽真正的原始碼求值） | 純函式、零 DOM，測得起來 |
| 被分享者改不到 `pet` | `tests/pet.test.mjs` 直接 import Worker 端的 `mergeSharedEdit` | 「路徑走不到」要有東西守著 |
| 選夥伴的面板真的按得動、開機畫面真的畫出夥伴 | `tools/smoke.mjs` | **CLAUDE.md 第 0 條**：`npm test` 與 `node --check` 都抓不到「函式根本沒被定義」 |
| 開機畫面的三個不變量仍然成立 | `tools/check-ambience.mjs`（既有九條 ＋ 新的） | 1200ms 上限要在 **JavaScript 關掉時**也成立 |
| bar 不讓任何一頁橫向溢出、點擊目標夠大 | `tools/check-mobile.mjs`，**中英文各一輪** | 新增的固定元素最容易溢出；英文字串比中文長（〈`align-items` 在 column 底下管的是寬度〉那次的教訓） |
| 新 UI 的對比 | `tools/check-contrast.mjs`，**要主動把它逼出來再量** | 「畫面上沒有這個元素，略過」是一條永遠不會執行的斷言 |

**每一條新測試都要突變驗證**：把修法拿掉，確認它真的會紅。測試過了不代表
它測到了要測的東西——探針 9 的第一版就是綠的，而綠的理由是錯的。
