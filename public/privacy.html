我們存了什麼

  • 你的排程：項目、會議、循環規則、專案與甘特圖（含專案說明書與任務狀態）、每日記錄與專案筆記、標籤、假日設定。這些是你自己輸入的。
  • AI agent 寫的進展紀錄：你連接 AI agent（Pro 功能）之後，agent 寫在專案裡的進展、交接筆記、提問、風險，以及你的回答與決定。這些紀錄只能新增、不能修改或刪除，只有你能把某一筆的內容遮蔽；專案刪除 30 天後一併清除。另外會存 agent 提出、尚待你審核的修改提案，與每條連線的設定（先審核、要求驗收、暫停）。
  • 帳號資料：email、密碼的雜湊（PBKDF2，永遠不存明文）、註冊時間、帳號狀態。
  • 第三方登入：你選擇 Google 或 Sign in with Apple 時，會儲存該服務提供的 subject、email 與登入來源，用來把不同裝置連到同一個本服務帳號。Apple refresh token 只用於你刪除帳號時撤銷 Apple credential。
  • App 交易資料：Apple 提供的 app 交易識別碼與購買日期，用來限制同一個 Apple 帳號重複建立 app 帳號。不含你的 Apple ID、姓名或付款資訊。
  • Pro 訂閱資料：訂閱商品識別碼、Apple 的原始交易識別碼、到期日與退款／撤銷日期，用來判斷 Pro 權利。付款資料由 Apple 處理，我們不會取得信用卡資料。
  • 網頁版訂閱資料：在網頁版訂閱時，會儲存 Paddle 的訂閱識別碼、客戶識別碼與到期日，用來判斷 Pro 權利。付款資料由 Paddle 處理，我們不會取得信用卡資料。
  • 登入中的裝置：裝置類型（例如「iPhone app」或「Chrome on Windows」）與最後使用時間。不記錄 IP 位址。
  • 推播資料：你允許推播後，會儲存 Apple APNs 裝置 token、環境與最後使用時間；你登出、取消註冊或 token 失效時會刪除。
  • GitHub PR 的標題與狀態：你把專案連到 GitHub 的 Pull Request（由 AI agent 回報，或由你設定的 GitHub webhook 送來）時，我們會存該 PR 的網址、編號、標題、分支名稱、作者帳號、狀態（草稿／開著／已合併／已關閉）、測試與審核結果，以及最後更新的時間與來源。我們不存你的 GitHub 帳密或 token，也不會主動去讀 GitHub；這些資料只來自 agent 或你設定的 webhook，只用在你自己的專案頁。若你設定 webhook，我們另外存一組只用來驗證「這是 GitHub 送來的」的簽章密鑰；你可以隨時重新產生或移除，刪除帳號時一併刪除。這些資料不在每日備份裡。
  • agent 通知的節流記錄：agent 向你提問或提案時，我們會寄一封信（有裝 app 也會推播），內容只有連線名稱、專案名稱與件數，不含問題或提案的內容。為了「同一個專案 30 分鐘內最多一封」，會記錄每個專案最後一次通知的時間與還沒通知的件數；刪除帳號時一併刪除。你可以在「我的帳號」關掉這一種通知。
  • 排程的版本歷史：Pro 帳號會在 AI agent 修改排程之前、你自己修改時（最多每小時一次）與每天一次，留下整份排程的副本，讓你可以比較差異或退回到過去的樣子。副本存在 Cloudflare R2，保留 30 天、每個帳號最多 300 份，之後自動刪除；刪除帳號時一併刪除，也不在每日備份裡。
  • 專案的唯讀分享連結：只有你主動產生連結時才會有。知道連結的人不用登入就能看到那一個專案的名稱、里程碑與任務狀態，以及你勾選要多公開的種類（進展日誌、提問、決策、風險、PR）；被你遮蔽的內容永遠不會出現。連結只存雜湊，你可以隨時重新產生或撤銷，刪除帳號時一併刪除。
  • 每週摘要信：預設關閉，只有你在「我的帳號」打開才會寄；內容只有專案名稱與件數，不含日誌或提問的內容，信裡有一鍵取消訂閱。
  • 分享記錄：你分享給誰、誰動過你分享的項目，保留 90 天。

存在哪裡

Cloudflare（Workers、D1 資料庫、R2 儲存）。資料庫位於亞太區。每天自動備份一次到 R2，保留最近 14 份；備份不含密碼雜湊。

誰看得到

  • 你的排程只有你自己看得到，以及你主動分享給的帳號（只看到你分享的那幾個項目）。
  • 如果你替某個專案產生了公開的唯讀分享連結，任何拿到這個網址的人不用登入就看得到那一個專案的名稱、里程碑與任務進度（加上你勾選要公開的其他內容）；說明書、筆記、每日記錄與其他專案永遠不在裡面。你隨時可以重新產生或撤銷，舊的網址當場失效。
  • 管理者看得到帳號的 email、狀態與操作記錄，看不到任何人的排程內容。
  • 我們不販售、不交換、不用於廣告。沒有第三方追蹤或分析工具。

會送到第三方的資料

  • AI 小幫手（你按下去才會用）：你當下的排程摘要會送到 DeepSeek 的 API 產生回答。不用這個功能就不會送。
  • 提醒信與驗證碼：透過 AgentMail 寄到你註冊的信箱。
  • Apple：App 內的購買與訂閱由 Apple StoreKit 處理；Apple 也會把已簽章的訂閱狀態通知送到本服務，用來更新續訂、到期與退款。
  • Paddle（只在網頁版訂閱時）：結帳由 Paddle.com 處理，你的 email、付款資料與所在國家由 Paddle 收集；本服務會把你的帳號識別碼附在那筆訂單上，Paddle 會把訂閱狀態的通知送回本服務。
  • Google：你選擇 Google 登入時，Google 會提供已驗證的登入 token；本服務只保留必要的帳號 subject 與 email，不會取得 Google 密碼。
  • 推播：開啟推播時，通知內容與 APNs token 會送到 Apple Push Notification service。
  • 字型：頁面會向 Google Fonts 取得字型檔；離線或封鎖時退回系統字型，功能不受影響。

保留多久

帳號與排程會保留到你刪除帳號。登入 session 會在期限到期或登出後失效；分享與管理記錄保留 90 天，寄信記錄保留 30 天，備份最多保留 14 份。訂閱事件只保留必要的交易識別碼與權利狀態。第三方登入身分在帳號刪除時刪除，Apple credential 同時要求撤銷。推播 token 在取消註冊或被 Apple 判定失效時刪除。

怎麼刪除

在 app 或網頁版的「我的帳號」分頁最下面按「刪除我的帳號」，輸入密碼確認。帳號、雲端上的所有排程、分享、行事曆訂閱與提醒設定會立即刪除；每日備份裡的副本會在 14 天輪替後自動消失。

你也可以隨時在「我的帳號」匯出一份完整的 JSON 備份。

Privacy Policy

Work Schedule · Last updated 2026-11-21

What we store

  • Your schedule: items, meetings, recurrence rules, projects and Gantt charts (including project briefs and task statuses), daily notes and project notes, tags, holiday settings. All of it is what you typed in.
  • AI agent progress records: if you connect an AI agent (a Pro feature), the progress notes, handoff notes, questions and risks it writes in a project, plus your answers and decisions. These records can only be added, never edited or deleted; only you can redact the content of an entry. They are removed 30 days after the project is deleted. We also store pending change proposals from the agent and each connection's settings (review first, require acceptance, paused).
  • Account data: email, a password hash (PBKDF2; plaintext is never stored), registration time, account status.
  • Third-party sign-in: if you choose Google or Sign in with Apple, we store the provider subject, email and provider name to connect your devices to the same Work Schedule account. An Apple refresh token is used only to revoke the Apple credential when you delete the account.
  • App transaction data: an app transaction identifier and purchase date from Apple, used to prevent repeated account creation with the same Apple account. We do not receive your Apple ID, name or payment details.
  • Pro subscription data: the product identifier, Apple original transaction identifier, expiry date, and refund/revocation date, used to determine Pro entitlement. Apple processes payment; we do not receive card details.
  • Web subscription data: if you subscribe on the web, we store Paddle’s subscription identifier, customer identifier and expiry date to determine Pro entitlement. Paddle processes payment; we do not receive card details.
  • Signed-in devices: device type (for example "iPhone app" or "Chrome on Windows") and last-used time. IP addresses are not recorded.
  • Push data: if you allow push notifications, we store Apple's APNs device token, environment and last-used time; it is deleted when you sign out, unregister, or the token becomes invalid.
  • GitHub pull request titles and states: when you link a project to a GitHub pull request (reported by an AI agent, or sent by a GitHub webhook you set up), we store the PR's URL, number, title, branch name, author username, state (draft / open / merged / closed), checks and review results, and when and by whom it was last updated. We never store your GitHub password or token and never fetch anything from GitHub ourselves; the data comes only from your agent or your webhook and is used only on your own project page. If you set up a webhook we also store a signing secret used only to verify that a request really came from GitHub; you can regenerate or remove it at any time, and it is deleted with your account. This data is not part of the daily backup.
  • Agent notification throttle records: when a connected agent asks you a question or proposes changes, we send an email (and a push if you use the app) containing only the connection name, the project name and a count — never the question or proposal itself. To send at most one per project every 30 minutes, we record each project's last notification time and how many are not yet notified; this is deleted with your account. You can turn this notification off in My account.
  • Schedule version history: for Pro accounts we keep a copy of your whole schedule before an AI agent changes it, when you change it yourself (at most once an hour) and once a day, so you can compare differences or go back. The copies are stored in Cloudflare R2, kept for 30 days and at most 300 per account, then deleted automatically; they are deleted with your account and are not part of the daily backup.
  • Read-only project share links: only created when you generate one. Anyone with the link can view, without signing in, that one project's name, milestones and task statuses, plus the kinds you tick (progress log, questions, decisions, risks, PRs); entries you redacted never appear. Only a hash of the link is stored; you can regenerate or revoke it at any time, and it is deleted with your account.
  • Weekly summary email: off by default and sent only if you turn it on in My account; it contains only project names and counts, never log or question content, and every email has a one-click unsubscribe.
  • Sharing log: who you shared with and who changed a shared item, kept for 90 days.

Where it lives

Cloudflare (Workers, D1 database, R2 storage). The database is in the Asia-Pacific region. A backup is taken daily to R2 and the latest 14 are kept; backups do not contain password hashes.

Who can see it

  • Only you can see your schedule, plus the accounts you choose to share with (they see only the items you shared).
  • Administrators can see account emails, status and the admin activity log. They cannot see anyone's schedule content.
  • We do not sell, trade or use your data for advertising. There are no third-party trackers or analytics.

Data sent to third parties

  • AI assistant (only when you use it): a summary of your current schedule is sent to DeepSeek's API to produce the answer. Nothing is sent if you don't use it.
  • Reminder and verification emails: delivered through AgentMail to the address you registered with.
  • Apple: in-app purchases and subscriptions are processed by Apple StoreKit. Apple also sends signed subscription-status notifications to this service so renewals, expiry and refunds can update your entitlement.
  • Paddle (only when you subscribe on the web): checkout is handled by Paddle.com, which collects your email, payment details and country. We attach your account identifier to that order, and Paddle sends subscription-status notifications back to this service.
  • Google: when you choose Google sign-in, Google provides a verified sign-in token; we store only the necessary subject and email and never receive your Google password.
  • Push notifications: when enabled, notification content and the APNs token are sent to Apple's Push Notification service.
  • Fonts: the page fetches font files from Google Fonts; offline or blocked, it falls back to system fonts with no loss of function.

Retention

Your account and schedule remain until you delete your account. Sign-in sessions expire or are revoked when you sign out; sharing and admin logs are kept for 90 days, mail logs for 30 days, and at most 14 backups are retained. Subscription events retain only the transaction identifiers and entitlement state needed to operate subscriptions. Third-party identities are deleted with the account, and the Apple credential is also sent for revocation. Push tokens are deleted when you unregister or Apple reports them invalid.

How to delete

At the bottom of the "My account" tab in the app or on the web, press "Delete my account" and confirm with your password. The account, every schedule in the cloud, shares, calendar feed and reminder settings are deleted immediately; copies inside the daily backups expire after the 14-day rotation.

You can also export a full JSON backup from "My account" at any time.
